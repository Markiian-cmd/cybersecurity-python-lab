# Лабораторна робота №3. Варіант 7

Сервіс обліку часу реагування на інциденти.
Категорії: **account**, **network**, **endpoint**.
Поле value - скінченний невід'ємний час у хвилинах (unit = minutes).
Поріг **30.0 хв** - параметр предметної області; значення 45.0, 60.0 і 1.5 допустимі.
Статуси new, in_progress, done позначають стан перевірки запису.

## Встановлення та запуск

Потрібен Python 3.10 або новіший. Виконуй команди PowerShell із кореня репозиторію.
Якщо середовища .venv ще немає, спочатку створи його:

~~~powershell
python -m venv .venv
~~~

~~~powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m labs.lab03.seed
.\.venv\Scripts\python.exe -m uvicorn labs.lab03.main:app --reload --host 127.0.0.1 --port 8000
~~~

- [Swagger UI](http://127.0.0.1:8000/docs): операція → Try it out → Execute.
- [OpenAPI](http://127.0.0.1:8000/openapi.json): схема API.
- Зупинка сервера: Ctrl+C. Режим --reload призначений для розроблення.

Ініціалізація під час запуску лише створює відсутні таблиці.
Окремо створити порожню базу можна командою:

~~~powershell
.\.venv\Scripts\python.exe -m labs.lab03.database
~~~

Шляхи обчислюються від розташування database.py; sys.path вручну не змінюється.

## Початкові дані варіанта 7

Категорії мають id: 1 = account, 2 = network, 3 = endpoint.
Назва кожного запису: «Вимірювання реагування NN».

| code | category_id | value, хв | status |
| --- | --- | --- | --- |
| V07-01 | 1 | 12.0 | new |
| V07-02 | 2 | 45.0 | in_progress |
| V07-03 | 3 | 20.0 | done |
| V07-04 | 1 | 35.0 | new |
| V07-05 | 2 | 60.0 | done |
| V07-06 | 3 | 18.0 | in_progress |
| V07-07 | 1 | 30.0 | done |
| V07-08 | 2 | 25.0 | new |

Seed перевіряє весь набір до вставлення. Три категорії та вісім записів
зберігаються однією транзакцією. За помилки скасовуються всі вставлення.
Повторний запуск seed повідомляє, що база непорожня, та зберігає наявні дані.

## API та приклади

| Метод і маршрут | Результат |
| --- | --- |
| GET /ping | 200, status = ok |
| GET /student | 200, ПІБ, група та variant_number = 7 із shared/student.py |
| GET /categories | 200, список категорій за id |
| POST /categories | 201, нова категорія; тіло: {"name": "training"} |
| DELETE /categories/{category_id} | 204, видалення порожньої категорії |
| GET /records | 200, список із фільтрами |
| POST /records | 201, нове вимірювання |
| GET /records/{record_id} | 200, одне вимірювання |
| PUT /records/{record_id} | 200, повна заміна змінюваних полів |
| DELETE /records/{record_id} | 204, видалення вимірювання |
| POST /records/bulk | 201, пакет із 1-100 вимірювань |

Тіло POST /records та PUT /records/{record_id}:

~~~json
{
  "code": "V07-DEMO",
  "title": "Вимірювання для демонстрації",
  "category_id": 1,
  "value": 45.0,
  "status": "new"
}
~~~

У PUT передаються всі п'ять полів. Id створює SQLite; відповідь містить
також category_name, отриману через JOIN. Невідомі поля заборонено,
пробіли навколо тексту обрізаються, порожній текст і некоректні числа відхиляються.

GET /records приймає category_id, status, min_value, q, limit (1-100, типово 20)
та offset (від 0, типово 0). Фільтри поєднуються через AND,
результати впорядковані за id. Пошук q є буквальним і враховує регістр.

~~~powershell
Invoke-RestMethod 'http://127.0.0.1:8000/ping'
Invoke-RestMethod 'http://127.0.0.1:8000/student'
Invoke-RestMethod 'http://127.0.0.1:8000/records?category_id=2&status=new&min_value=25&limit=5&offset=0'
~~~

На початковому наборі останній запит повертає V07-08.
Фільтри без збігів, зокрема за відсутньою категорією, повертають 200 і [].

Помилки: 404 - ресурс або потрібна категорія відсутні; 409 - дублікат code,
назви категорії чи видалення непорожньої категорії; 422 - некоректні дані;
500 - технічна помилка, подробиці якої записуються в журнал.
Відповіді 204 мають порожнє тіло.

POST /records/bulk приймає JSON-масив таких самих об'єктів.
Pydantic спочатку перевіряє весь масив. Перевірка категорій і вставлення
виконуються однією транзакцією: помилка другого елемента скасовує також перший.
Усі SQL-значення передаються через ? або іменовані параметри (:code, :title). З'єднання закриваються після операцій.

## Завдання 3: ручна перевірка у Swagger

Для кожного запиту: Try it out → заповнити параметри/JSON → Execute.
Фіксуй Server response, HTTP-код і тіло відповіді у звіті.

| № | Перевірка | Очікуваний результат |
| --- | --- | --- |
| 1 | Seed двічі; GET категорій і записів | У новій базі 3 категорії, 8 записів; повторний seed не змінює стан |
| 2 | GET /ping, /student, /categories | 200, правильні дані варіанта 7 |
| 3 | POST, GET, PUT, DELETE одного запису | 201, 200, 200, 204; id під час PUT незмінний |
| 4 | min_value=30; category_id=1 разом зі status=new; limit=2, offset=2 | Фільтрація та стабільний порядок |
| 5 | value=-1, title="   ", status="wrong", limit=0 | 422, записи не змінюються |
| 6 | value="minutes" | 422; дробове числове 1.5 для варіанта 7 дозволено |
| 7 | GET /records/9999999; POST із category_id=9999999 | 404 |
| 8 | POST із code=V07-01; категорія з name=account | 409, попередні дані збережено |
| 9 | Видалити категорію 1; створити й видалити порожню категорію | 409 та 204 |
| 10 | POST /records/bulk з двома новими кодами | 201, обидва записи збережено |
| 11 | Пакет: перший новий, другий із code=V07-01 | 409, жоден новий запис не збережено |
| 12 | Пакет: перший новий, другий із category_id=9999999 | 404, жоден новий запис не збережено |
| 13 | GET /records із q=' OR 1=1 -- | 200, рядок обробляється як дані; стан бази не змінився |
| 14 | Створити запис, зупинити сервер Ctrl+C, запустити знову, GET за тим самим id | Запис доступний після перезапуску |

Приклад JSON пакета для сценарію 11:

~~~json
[
  {"code":"V07-ROLLBACK","title":"Перший новий запис","category_id":1,"value":12.0,"status":"new"},
  {"code":"V07-01","title":"Другий запис із дублікатом","category_id":2,"value":45.0,"status":"new"}
]
~~~

Для сценарію 10 задай обом елементам нові унікальні code.
Для сценарію 12 другому елементу задай новий code та category_id=9999999.
У сценаріях 11-12 зафіксуй кількість до/після та відсутність першого code.
Читай усі сторінки: limit=100, offset=0, 100, 200 ... до завершення списку.
